SNLP 2026 / Paper Reading Plan

内部の truth signal から、外部の review design へ

2本の論文を、単なる paper reading ではなく、 「LLM は正しさを内部にどう持ち、それを利用可能な形でどう外へ出せるか」という流れで読む。

Starting Point

元の関心は、情報抽出の信頼性出力だった

実務上の問い

  • LLM に `confidence: 0.87` を出させる意味はあるか。
  • それとも `needs_review` のような行為ラベルがよいか。
  • 根拠スパン、null、曖昧性をどう出力に含めるか。

暫定結論

  • 細かい連続値の微差には意味が薄い。
  • 主出力は根拠付きレビュー判定に寄せる。
  • 連続値が必要なら後段で監査可能な信号から作る。
  • 5段階程度の review level は有用そう。

ここから出てきた読書上の問い: 内部に truth-sensitive な信号があるとして、 それは confidence、abstention、review 判定として信頼できる形で外に出せるのか。

Paper 1

LLM Beliefs Are in Their Heads

LLM に belief があると雑に言うのではなく、belief-like representation が満たすべき基準を Accuracy / Use / Coherence / Uniformity に分けて検査する。

強い点 truth-sensitive な中間表現が大きいモデルで見える。steering により出力の truth-value 判断も変わる。
面白い点 attention head が residual stream より局所的で、介入効果も出やすい可能性がある。

Paper 1 / Terms

4基準は「信念らしさ」の別々の条件

この論文の Accuracy / Use / Coherence / Uniformity は、通常のモデル評価指標というより、 内部表現が belief-like と言えるための条件として使われている。日本語では次のように読むと説明しやすい。

英語 日本語での読み 何を問うか 実験での見方
Accuracy 真偽分離性 / 分離精度 内部表現が true input と false input を分けているか。 final token の residual stream や head output から、linear probe で True/False を分類する。
Use 機能的使用 / 出力への関与 読める truth signal が、実際にモデルの出力計算に使われているか。 truth direction に沿って activation を steering し、True/False logits が動くかを見る。
Coherence 整合性 p, not-p, p and q, p or q などの論理関係に対して一貫するか。 logical paraphrase で probe が崩れないか、calibrated pseudoprobability が確率制約を満たすかを見る。
Uniformity 領域横断的一様性 / ドメイン一貫性 都市・企業・数比較・翻訳など、異なる domain でも同じような truth direction が使えるか。 ある domain で訓練した probe が、別 domain の True/False 文にも generalize するかを見る。

発表では、Accuracy は「読めるか」、Use は「使われているか」、Coherence は「矛盾しないか」、 Uniformity は「別領域にも通用するか」と言い換えると、実験の役割が分かりやすい。

Transformer Refresher 1

residual stream は、層をまたぐ共有の通路

ある1つの layer 出力時点で見る residual stream の形は 入力 token 数 x d_model。 全 layer 分を解析用に保存すると layer 数 x 入力 token 数 x d_model になる。 `d_model` は token embedding と residual stream に共通する埋込次元数である。

  • 読む
    Attention と MLP は、その時点の stream を入力として使う。
  • 足す
    計算結果は上書きではなく、基本的に stream へ加算される。
  • 形
    1 layer では 入力 token 数 x d_model。全 layer を保存すると layer 数 x 入力 token 数 x d_model。

Transformer Refresher 2

attention head は「どこを見るか」と「何を書くか」を分けて考える

  • QK
    query と key で、どの過去 token から読むかを決める。
  • OV
    value と output で、読んだ内容をどう stream に書くかを決める。
  • head 単位
    論文の probe は QK/OV を分解せず、head output 全体を読む。

5.1 Accuracy

Accuracy は、内部ベクトルから真偽ラベルを読めるか

  • LLM 入力
    文だけ。True / False は prompt に入れない。
  • probe 学習
    取り出した activation に、外部の正解ラベルを対応づける。
  • 意味
    内部表現に truth-sensitive な方向があるかの最低条件チェック。

5.1 Accuracy / Dataset

約1.3万文の True/False 文から activation を集める

Accuracy 実験では Samuel Marks and Max Tegmark (2024), The Geometry of Truth の True/False dataset を使う。文だけを LLM に入力し、final token 位置の residual stream / head output を取り出す。True/False ラベルは後から linear probe の教師ラベルとして使う。

domain 文数 例文 label
Cities 1,496 The city of Hangzhou is in China. True
Common Claims 4,450 Wild monkeys groom each other’s hair as a social activity. True
Companies 1,200 Barclays has headquarters in Russia. False
Larger 1,980 Fifty-six is larger than fifty-three. True
Smaller 1,980 Sixty-five is smaller than eighty-seven. True
Sp_En_Trans 354 The Spanish word ‘madre’ means ‘mother’. True
Counterfact 2,000 Klemens von Metternich’s profession is an actor. False

合計は約13,460文。Accuracy では半分を Use 実験用に予約し、残り半分で probe を訓練・評価する。 1文につき、各 layer の final-token residual vector と、各 layer・各 head の final-token head output を読む。

5.1 Accuracy / Results

大きい Llama / Gemma 系では真偽をかなり読める

層や head の強さは、probe の重みの大きさではなく、その layer / head の activation だけで True/False を分類した test accuracy で見る。本文では residual stream の Top-3 probe accuracy と、 head-level の傾向が報告されている。

モデル 本文での residual probe accuracy 読み方
GPT-2 Large 0.567 ほぼ chance に近く、truth-sensitive encoding は弱い。
Yi 0.630 読めるが弱い。
Pythia 0.721 中程度に読める。
Llama 0.889 かなり高精度に読める。
Gemma 0.920 非常に高精度に読める。
モデル Residual Heads 補足
GPT-J 0.799 0.718 上位5 activation 平均。以後の実験では baseline 的に扱われる。
Llama 0.895 0.857 residual stream からも強く読める。
Llama Instruct 0.882 0.899 instruction tuning 後も head-level signal が強い。
Gemma 0.916 0.911 residual / heads がほぼ同程度。
Gemma Instruct 0.923 0.925 head-level でも非常に高い。

まとめ: residual stream 全体からも True/False は読める。一方で、全 head が同じではなく、 一部の layer・一部の head output に truth signal が局所的に現れる。これは 5.2 Use で steering 対象を選ぶ根拠になる。

5.2 Use

読める truth direction は、出力も動かせるのか

Accuracy は「内部から真偽を読めるか」だった。Use は一歩進んで、Accuracy で見つけた truth-sensitive direction に沿って activation を steering し、モデルの True/False 出力が 実際に変わるかを見る。

1. direction を作る

True 文の activation 平均と False 文の activation 平均の差を取る。

truth direction
= mean(True activations)
- mean(False activations)
→
2. activation を動かす

上位 K 個の truth-sensitive layer / head output に方向ベクトルを足す。

activation'
= activation
+ alpha * direction

目的は「わざと間違った truth-value answer を引き出せるか」。False → True と True → False の両方向で、正解 token と不正解 token の確率が介入前後でどう動くかを見る。

5.2 Use / Prompt

出力は True / False / Unknown に縛っている

Use 実験は、自由な自然文生成を観察しているわけではない。プロンプトで回答形式を True / False / Unknown に制限し、その条件下で activation steering が truth-value 出力確率を 動かすかを測る。 

Determine whether the following statement is factually correct.
Respond with exactly one of: True, False, Unknown.
Answer Unknown unless you are certain.

{STMT}
Answer:
この実験で言えること
  • この prompt / 出力形式のもとで、truth direction が True/False logits を動かす。
  • random direction より truth direction の効果が出るかを比較できる。
  • probe で読めるだけでなく、出力計算に関与する可能性を見られる。
この実験だけでは言えないこと
  • 別の回答形式で、同じ signal がどう表面化するか。
  • 自然文説明、`not` 付与、情報抽出 JSON などへの変換。
  • 内部 truth signal がそのまま confidence や needs_review になるか。

5.2 Use / Results

head steering は小さい介入で効きやすい

Llama / Gemma 系では steering が概ね成功し、GPT-J は反応が弱い。instruction-tuned models は base models より steering sensitivity が大きく、attention head への介入は residual stream より 小さい intervention strength で効果を出しやすい。

model direction Residual effect Head effect 読み方
Llama Instruct False → True 1.23 1.23 どちらも強く出力を動かす。
Llama Instruct True → False 0.90 1.23 head 側も強い。
Gemma Instruct False → True 0.54 0.87 head steering の効果が大きい。
Gemma Instruct True → False 1.07 1.48 head steering が最も強い。
GPT-J False → True 0.05 0.05 ほぼ動かない。
GPT-J True → False 0.20 0.09 弱い baseline 的な挙動。

解釈: truth-sensitive direction は単に probe で読めるだけではなく、少なくともこの True/False 出力設定では downstream computation に機能的に関与している可能性がある。

5.3 Coherence

真偽を読めても、論理的に一貫するとは限らない

Coherence は、truth-sensitive representation が否定・連言・選言に対してどれくらい整合的かを見る。 belief-like と言うなら、少なくとも p と not-p を同時に強く true っぽく表現していては困る。

logical coherence

元の True/False 文から negation, conjunction, disjunction を作り、probe が分類できるかを見る。

p: Hangzhou is in China.
not p: Hangzhou is not in China.
p and q
p or q
probabilistic coherence

probe の連続出力を疑似確率として読み、確率的な制約を満たすかを見る。

P(p) + P(not p) ≈ 1
P(p and q) <= P(p)
P(p) <= P(p or q)

ここは本論文の慎重に読むべき部分。Accuracy と Use は強いが、Coherence は中程度で、特に negation が弱い。

5.3 Coherence / Calibration

probe のスコアを、確率らしく補正して使う

logistic regression probe は、activation からまず連続スコアを出す。このスコアは True/False 分類には使えるが、 そのまま `P(true)` として信頼できるとは限らない。そこで validation data に合わせて calibration する。

raw probe output 
score = w · activation + b
p_raw = sigmoid(score)

`p_raw = 0.8` が本当に「80% true」を意味するとは限らない。

→
calibrated pseudoprobability 
p_hat = calibrate(p_raw)

isotonic regression で、実際の頻度に合うように 0-1 の値へ補正する。

例 coherent に近い coherent でない
p `P_hat(p) = 0.91` `P_hat(p) = 0.85`
not p `P_hat(not p) = 0.12` `P_hat(not p) = 0.78`
合計 `1.03`: だいたい 1 `1.63`: p も not-p も true っぽい

これはモデル自身の主観確率そのものではない。activation から probe で読み出した値を、 確率的制約の検査に使えるよう補正した pseudoprobability である。

5.3 Coherence / Results

Coherence は中程度、negation が弱い

logical task では全体として中程度の coherence が見られる。ただし Common Claims の negated statements で linear probes の accuracy が落ちる。probabilistic experiment では、calibrated logistic regression probes が self-report や logits より coherent な probability を出す場合がある。

model negated common claims accuracy 読み方
Llama 0.51 ほぼ chance。
Llama Instruct 0.59 少し改善するが弱い。
Gemma 0.56 弱い。
Gemma Instruct 0.67 相対的には良いが十分強くはない。
GPT-J 0.44 chance 未満。

解釈: truth direction はあるが、線形 probe だけでは generalized negation を安定して扱えない。 情報抽出では negation、条件、absent/null、unsupported inference に注意が必要になる。

5.4 Uniformity / Setup

同じ truth direction は、別 domain でも使えるのか

Uniformity は、Accuracy で見つけたような truth-sensitive direction が、特定 domain 専用ではなく 複数 domain にまたがって使えるかを見る。実験としては steering ではなく、probe の cross-domain accuracy を測る。

手順 内容 読み方
1. 使う場所を決める Accuracy でよかった model の best layer / best head を使う。 全 layer/head を再探索するのではなく、truth signal が強い場所で検査する。
2. train domain を変える Common Claims、単一 domain、複数 domain の組み合わせで probe を訓練する。 汎用文だけで足りるか、特定 domain 依存か、多様な訓練が必要かを見る。
3. test domain を変える Cities、Companies、数比較、翻訳など別 domain の True/False 文で評価する。 train していない domain でも True/False を分離できれば uniformity が高い。
4. logical paraphrase は除外 negation などを含む拡張 dataset は混ぜない。 Coherence の失敗、特に negation の弱さで Uniformity の評価が濁るのを避ける。

したがって 5.4 は「別領域で Accuracy が保たれるか」の実験であり、Use のように activation steering で出力を動かす実験ではない。

5.4 Uniformity / Results

多様な domain で訓練すると、truth direction はかなり一般化する

結果は residual level と head level の両方で強い。特に複数 domain を含む大きな訓練セットでは、 各 test domain への平均 accuracy が高く、worst domain でも chance をかなり上回る。 instruction-tuned models は base models より cross-domain consistency が高い傾向がある。

train set model average / worst test acc. 読み方
large multi-domain Llama 0.87 / 0.74 平均も worst も高く、domain 専用方向ではなさそう。
large multi-domain Llama Instruct 0.87 / 0.72 base と同程度に強い。
large multi-domain Gemma 0.88 / 0.68 平均は高いが、弱い domain は残る。
large multi-domain Gemma Instruct 0.90 / 0.74 この設定では最も安定。
Common Claims only Llama / Llama Instruct 0.64 / 0.57, 0.75 / 0.58 汎用文だけでも一部 generalize するが、worst は弱い。
Common Claims only Gemma / Gemma Instruct 0.75 / 0.66, 0.77 / 0.50 平均は良いが、domain によって崩れる。

解釈: literal / factual な True/False 文に限れば、truth signal はかなり domain-robust。 ただし皮肉・比喩・語用論的転用のように、文脈で命題内容が変わるケースまでは検査していない。

Paper 2 / Post-training

比較軸は post-training

この論文のモデル選定は、モデルを広く並べるというより、pretraining 後にどんな訓練を足したかを見る設計である。 同じくらいのサイズや近い系列で、Instruct、SFT reasoning、RL reasoning を比べる。

pretrained base

大量テキストで next-token prediction を学習した土台。ここだけでは、指示追従や confidence 表明は安定しにくい。

→
post-training

SFT や RL で、指示追従、長い reasoning chain、自己反省的な振る舞い、alignment を後から強める。

post-training の種類 訓練のイメージ 代表モデル この論文での関心
general instruction / alignment ユーザー指示に従う、答えの形式を守る、安全性や有用性を高める。 Qwen2.5-14B/32B-Instruct, DeepSeek-V3 通常の instruct model は confidence calibration の基準線になる。
reasoning SFT 長い chain-of-thought や reasoning trace を真似る。 DeepSeek-R1-Distill-Qwen-14B/32B 推論能力だけでなく、verbalized confidence もよくなるか。
reasoning RL 結果の良さを報酬にして、探索・検算・反省的 reasoning を強める。 DeepCoder-14B, Skywork-OR1-32B, DeepSeek-R1 SFT よりさらに confidence と correctness の対応が改善するか。

「どの（pretrained）モデルが確信度の表明を得意とするか」ではなく
「post-training が確信度の表明にどう効くか」を調べている

Paper 2 / Prompting 1

confidence は、出力として言わせて測る

この論文は内部 activation を読まず、モデルに回答と confidence を XML 形式で出させる。 その confidence と実際の正誤がどれくらい合うかを ECE / ACE / AUROC / AUPRC で測る。

prompting strategy confidence の出させ方 例 狙い
Vanilla CoT step-by-step で解かせ、最後に 0%--100% の confidence score を出させる。 `<confidence>80%</confidence>` 通常の verbalized confidence の基準線。
Vanilla CoT w. Prob 同じく解かせるが、confidence を 0.0--1.0 の probability score として出させる。 `<confidence>0.8</confidence>` 確率値として聞くと calibration が改善するという先行研究を確認する。
Self-reflection 1回目で回答を出させ、2回目でその problem と solution を見せて confidence だけを評価させる。 `solution` を再読して `<confidence>80%</confidence>` 一度答えたあとに自己評価させると、正誤認識が改善するかを見る。

ここで測っているのは「内部に truth signal があるか」ではなく、モデルが外に出した confidence が empirical accuracy と合うかである。

Paper 2 / Prompting 2

prompt 比較は、結論が prompt 依存でないかを見る保険

verbalized confidence は prompt に敏感なので、単一の聞き方だけだと 「その形式で聞いたからそうなっただけ」と言われやすい。そこで著者らは3種類の prompting strategy を並べ、 training paradigm と scale の効果が prompt を変えても残るかを確認する。

比較で切り分けたいもの
  • reasoning SFT / reasoning RL による calibration 改善。
  • 0%--100% と 0.0--1.0 の表現形式の差。
  • 自己反省 prompt が confidence を下げるか、逆に過信を増やすか。
  • reasoning-heavy task と factuality task で効果が変わるか。
読むときの注意
  • Self-reflection は内部監視ではなく、追加 prompt による外部的な再評価。
  • probability score は calibrated probability ではなく、モデルの自己申告。
  • 主結論は prompt 技法そのものより、post-training と model scale の違いに置かれている。

結果として、reasoning benchmarks では RL reasoning models が複数 prompt で安定して良い。 一方、factuality では小規模 reasoning models の miscalibration が残り、Self-reflection の効き方も dataset 依存になる。

Paper 2 / Results 1

reasoning-heavy tasks では、推論訓練で accuracy も calibration も改善

AIME や LiveBench-Reasoning では、Instruct から SFT reasoning へ進むと accuracy が大きく上がり、 ECE も下がる。さらに RL reasoning は、SFT 後に calibration / failure prediction を追加で改善する傾向がある。

比較 task Acc ↑ ECE ↓ AUROC ↑ 読み方
Qwen2.5-14B Instruct AIME 11.3% 0.760 0.670 低精度かつ過信寄り。
R1-Distill-Qwen-14B AIME 46.7% 0.342 0.847 SFT reasoning で大きく改善。
DeepCoder-14B AIME 57.7% 0.222 0.873 RL reasoning でさらに calibration が良い。
Qwen2.5-32B Instruct LiveBench 42.7% 0.472 0.556 難しい reasoning では confidence が弱い。
R1-Distill-Qwen-32B LiveBench 73.3% 0.152 0.777 SFT reasoning で精度・較正とも改善。
Skywork-32B LiveBench 84.7% 0.074 0.876 RL reasoning が最も良い。
DeepSeek-V3 → R1 LiveBench 50.0% → 89.3% 0.389 → 0.081 0.696 → 0.908 大規模 RL reasoning で強い改善。

結論: reasoning-heavy な問題では、長く考えられるようにする訓練は性能だけでなく verbalized confidence の信頼性も改善しやすい。

Paper 2 / Results 2

factuality では、reasoning model が「分からない」と言いにくくなる

SimpleQA / FreshQA では、reasoning models は `I don't know` に相当する not attempted response を大きく減らす。 しかし、小規模モデルでは accuracy が十分に上がらず、むしろ calibration が悪化する場合がある。

Calibration: confidence と実際の正答率が合っていること。たとえば confidence 70% と言った問題群が 実際に約70%正しければ well-calibrated。ECE は confidence ごとに bin 分けし、 各 bin の「平均 confidence」と「実正答率」のズレを重み付き平均した値で、小さいほどよい。

Paper 2 / Results 3

prompt を変えても、主因は training paradigm と scale

Vanilla CoT、probability score variant、Self-reflection を比べても、reasoning benchmarks では RL reasoning models が安定して低い ECE を示す。一方、factuality では prompt の効き方が dataset によって変わる。

観点 代表値 読み方
AIME: 14B 系 Qwen2.5-14B ECE 0.760、R1-Distill 0.342、DeepCoder 0.222 prompt 以前に、reasoning post-training の差が大きい。
AIME: Self-reflection Qwen2.5-32B 0.752 → 0.289、Skywork-32B 0.183 → 0.076 SR は一部 reasoning tasks で ECE を下げる。
SimpleQA DeepSeek-R1 0.324 → 0.551、small reasoning models も高 ECE SR が factuality で常に効くわけではなく、過信を増やす場合がある。
FreshQA 多くの小規模モデルで SR は ECE を下げる。例: Qwen2.5-14B 0.436 → 0.287 FreshQA では SR が助けになることがある。

著者の読み: prompting strategy は calibration を動かすが、支配的なのは RL を含む post-training と model scale である。

Development / The Confidence Dichotomy

次の発展: confidence は tool の種類でも大きく変わる

`Thinking Out Loud` は、主に「モデルが単発の問題に答えるとき、confidence が正答率に対応しているか」を見る。 `The Confidence Dichotomy` はこれを tool-use agent に広げ、外部ツールが confidence をどう歪めるかを調べる。 後者は calibration in LLMs の先行研究として `Thinking Out Loud` を明示的に参照している。

観点 Thinking Out Loud The Confidence Dichotomy
問題設定 reasoning / factuality task に答え、最後に confidence を表明する。 agent が web search や code interpreter を使いながら答え、confidence を表明する。
中心的な問い 推論訓練で「正しいときに高く、間違うときに低く」言えるようになるか。 tool を使うと calibration は一律によくなるのか、それとも tool type に依存するのか。
発見 reasoning-heavy task では改善するが、factuality では abstention が弱くなることがある。 evidence tool は過信を強め、verification tool は一部 grounding になる、という二分が出る。
tool type 例 confidence への作用 直感
evidence tool web search / retrieval / RAG 誤答時の confidence が上がりやすい。 検索結果はもっともらしい証拠を返すが、答えの正誤を直接検証しない。
verification tool code interpreter / calculator / SQL / solver 過信を抑えやすいが、完全ではない。 実行エラーや計算結果という deterministic feedback がある。

発展としての読み方: 「reasoning post-training は confidence をどう変えるか」から、 「外部証拠・外部検証を組み込む agent では confidence の意味がどう変わるか」へ進む。

Development / Calibration-Aware Training

対策の方向: accuracy だけでなく calibration も報酬に入れる

`The Confidence Dichotomy` は、標準的な tool-use RL では search agent の過信が残るため、 CAR（Calibration Agentic RL）を提案する。出力に confidence タグを要求し、正答と confidence の対応も報酬化する。

要素 説明 この論文での意味
format reward agent の reasoning / action / observation の形式に加え、`<confidence>` の出力を要求する。 confidence を後付け評価ではなく、agent の通常出力の一部にする。
Brier 系 reward 正答なら高 confidence、誤答なら低 confidence が得になるようにする。 ただし重み次第では accuracy が落ちる、または reward hacking 的になる。
MSCR 正答の最低報酬が、誤答の最高報酬より常に高くなるように margin を入れる。 「低 confidence の誤答」が「低 confidence の正答」に勝つ抜け道を塞ぐ。
結果 読み方
Search agent で ECE が大きく低下。最大で約68%の相対改善。 evidence tool による過信は、専用の calibration-aware RL でかなり抑えられる。
Serper API など noisy web setting でも改善が残る。 ローカル Wikipedia retriever にだけ過適合したわけではない、という主張。
code interpreter 型の TIR でも改善するが、難問では ECE が高く残る。 verification tool は grounding になるが、最終的な calibration はモデルの推論能力にも縛られる。

`Thinking Out Loud` への接続: 「推論訓練だけでは知らないと言えない」なら、 次の工学的対策は「abstention / confidence を reward や fine-tuning objective に明示的に入れる」方向になる。

Related Work / Mitigation Lines

周辺研究は「confidence を明示的に学習対象にする」方向へ伸びている

研究 主な対象 何を足しているか この発表での位置づけ
The Hallucination Tax of Reinforcement Finetuning reasoning RFT と unanswerable math 標準 RFT が refusal を壊すことを示し、SUM という unanswerable data を少量混ぜる。 `Thinking Out Loud` の「知らないと言えない」問題とかなり近い。
Beyond Binary Rewards / RLCR reasoning model の confidence 正誤の二値報酬に Brier score を加え、confidence を報酬に入れる。 `The Confidence Dichotomy` の CAR / MSCR の直接の土台に近い。
ADVICE verbalized confidence confidence が自分の答えに依存しない answer-independence を問題化し、answer-grounded に fine-tune する。 「答えたあとに本当にその答えを見て confidence を言っているのか」という切り口。
LoVeC long-form generation 長文中の各 statement に、その場で数値 confidence を付けるよう RL で訓練する。 QA から、事実記述の連続である長文生成へ拡張する方向。
Abstain-R1 unanswerable query 単なる “I don’t know” ではなく、何が足りないかを説明する clarification も reward 化する。 abstention を「拒否」ではなく、次に必要な情報を返す行為として扱う。
LLMs Must Be Taught to Know What They Don’t Know 不確実性推定一般 少量の graded examples と LoRA で、プロンプトだけより良い uncertainty estimator を作る。 重い RL だけでなく、軽い fine-tuning / probe 的な実用路線もあることを示す。

まとめ: confidence / abstention は、prompt で引き出すだけでは不安定。 最近の流れは「正答率とは別の学習信号として、confidence・拒否・clarification を明示的に入れる」方向。

Working Hypothesis

内部信号があっても、外にうまく出るとは限らない

内部 LLM は truth-sensitive な表現を持ちうる。 ただしそれは局所的で、論理的に完全に coherent とは限らない。
→
外部 モデルが言う confidence はタスク・訓練・prompt に依存する。 factuality では過信や非 abstention が問題になる。

ここでの留保: true/false の内部表現、confidence の自己申告、abstention の行動は別物である。 だから情報抽出では「もっと推論させれば信頼性も上がる」とは限らない。

Prompt Design

confidence ではなく、レビュー行為へ接続する

0-100% の細かい連続値ではなく、根拠つきの status と review level を出す。 これは確率の自己申告ではなく、人間の作業を決めるラベルである。

auto_accept
根拠が明示的で schema に合う。
light_check
低リスクなら採用可。重要用途では確認。
review
通常レビュー。値はあるが判断余地あり。
priority_review
候補複数、曖昧、高リスク。
cannot_extract
根拠不足、矛盾、unsupported。

情報抽出プロンプトへの戻し方

3本目として読まないことにした `Certainty in Uncertainty` からも、反面教師的な示唆は残る。 不確実性は、数値化されるだけでは不十分で、coverage や decision rule に接続されて初めて使える。 

{
  "field": "target_field",
  "value": "抽出値。なければ null",
  "status": "extracted | absent | ambiguous | unsupported",
  "evidence_span": "抽出値を直接支持する原文",
  "source_location": "page/section/chunk id",
  "review_level": "auto_accept | light_check | review | priority_review | cannot_extract",
  "needs_review": true,
  "review_reason": "レビューが必要な理由"
}

LLM に `confidence: 0.84` を自己申告させるより、値・根拠・状態・レビュー理由を出させる。 連続 score が必要なら、後段で evidence span、schema 適合、複数抽出一致などから作る。

  3. Coherence が弱いなら、情報抽出でどの field が危ないか。

Expected Takeaway

論文紹介の狙い

「LLM は何を知っているのか」から一歩進めて、 「内部の信号を、利用者が信頼できる操作にどう変換するか」を議論する。

  • 1本目: 内部表現には truth-sensitive な信号がある。
  • 2本目: その信号が外部の confidence / abstention として安定するとは限らない。
  • 実用: 数値 confidence ではなく、根拠・status・review level へ落とす。
  • 留保: truth / confidence / abstention は接続できるが、同一視はしない。

QA

この Transformer 説明は、どこまで一般化できるか

ここでの説明は、Transformer 全般に共通する部品説明を含むが、論文の実験としては decoder-only autoregressive LLM を前提に読むのが安全である。特に final token の activation を取り出して truth-sensitive representation を probe する読み方は、GPT 系の decoder-only model に寄った説明である。

話題 適用範囲 説明での注意
token が embedding され、各層でベクトル表現が更新される Transformer 全般 encoder-only、decoder-only、encoder-decoder のどれにも共通する基本構造。
`d_model` と residual stream の形 Transformer 全般で使える基本整理 `d_model` は token embedding と residual stream に共通する埋込次元数。1 layer 出力時点では `入力 token 数 x d_model`、全 layer 分を保存すると `layer 数 x 入力 token 数 x d_model`。
residual connection により、各 layer の出力が元の表現に足し込まれる Transformer 全般 「上書き」ではなく「加算で更新される」と説明すると、residual stream の直感につながる。
residual stream を、各部品が読み書きする共有通路として見る 主に mechanistic interpretability でよく使う見方。decoder-only / encoder-only のどちらにもかなり有効 厳密な標準用語というより、解釈研究で便利な抽象化。今回の論文では residual stream と attention heads の両方を probe する。
attention head を QK と OV に分けて考える multi-head attention を持つ Transformer 全般 QK は「どこから読むか」、OV は「読んだ情報をどう書くか」という説明が有用。ただし実装により細部は異なる。
causal mask により、未来 token を見ずに過去 token だけを見る decoder-only autoregressive model、および encoder-decoder の decoder 側 BERT のような encoder-only model では通常この制約はない。今回の対象モデルは decoder-only なので、この前提でよい。
final token の activation を取り出して probe する decoder-only LLM で特に自然 次 token prediction の直前に、文全体についての情報が final token 位置へ集約されやすい、という読み方になる。
unembedding により residual stream から次 token logits を出す decoder-only autoregressive LM で中心的 encoder-only model では、そのまま次 token logits に読むわけではない。分類 head や masked LM head など別の出力構造になる。
True / False ラベルを prompt に入れず、後から activation に対応づけて probe を学習する probe 実験一般に広く使える 今回の Accuracy は「LLM がラベルを見て答える」実験ではなく、「ラベルなし入力時の内部表現から真偽を読めるか」の実験。
BERT など encoder-only model への拡張 activation に教師ラベルを対応づけて probe すること自体は可能。ただし decoder-only と同じ final-token next-token prediction としては読まない `[CLS]` 表現や各 token 表現を probe するなど、どの位置を代表表現とみなすかを別途決める必要がある。
T5 など encoder-decoder model への拡張 probe 実験は可能。ただし truth-sensitive signal を encoder 側、decoder 側、cross-attention 側のどこで読むかを設計し直す必要がある どこに truth-sensitive representation があるのかを、decoder-only より細かく切り分ける必要がある。
`LLM Beliefs Are in Their Heads` の実験対象 decoder-only autoregressive transformers GPT-2、GPT-J、Pythia、Llama、Gemma、Yi など。発表ではここを明示すると過剰一般化を避けられる。

まとめると、部品説明は Transformer 全般の入口として使える。ただし、この論文の結果は decoder-only LLM の residual stream / attention heads、とくに final token 周辺から truth-sensitive signal を読む実験として説明するのがよい。
